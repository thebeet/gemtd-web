# 代码库分析与重构记录

本次以工作区当时的实际代码为基线，包括已有的单机 Worker、房间模式和 README 未提交改动。保留这些功能，在现有实现上整理依赖方向、重复规则、存储和视图职责。

## 项目与功能边界

这是一个 Vue 3 + TypeScript + Three.js 的宝石塔防应用。`main.ts` 挂载 `TowerGame.vue`，根路径跳转到 `/game`；仓库已没有旧 README 描述的 Markdown 编辑器、画板或体素应用实现。Vite 提供开发和打包，Node HTTP 服务承载静态资源、Yjs 和战斗 WebSocket。

地图为 37×37 网格，包含两个禁建角区、五个途经点和初始岩石。建造阶段随机放置五个候选塔，随后保留、升阶或合成，其余候选格变为岩石。基础塔共有八类，JSON 每类包含六档属性，而普通建造流程使用五档品质；合成配方共有 38 个。数据层保留全部六档属性。

战斗数据包含 50 波，涉及地面/飞行路径、多人难度、攻击间隔与射程、弹道、物理/魔法伤害、暴击、溅射、持续伤害、控制与光环、怪物被动、经验金币、MVP 和合成伤害继承。界面提供塔/怪物详情、光环范围、排行榜、事件记录、预设和自定义迷宫、存档、相机切换及作弊测试工具。

单机使用浏览器 Worker；联机使用服务端权威模拟。两种模式均以 50ms 推进战斗，通常每两个 Tick 发送快照。联机另外通过 Yjs 同步地图和玩家建造状态，浏览器负责展示和插值。

## 原有问题与落地调整

1. Worker 直接导入服务端 WebSocket 处理函数，并把伪造连接和请求强转为 `never`。现在通过 `createGameHost()` 创建独立引擎，服务端仅解析房间 URL；Worker 使用同一引擎和显式连接接口。房间、怪物和弹道序号属于引擎实例，引擎提供 Tick 与释放方法；导入核心模块本身不启动计时器。
2. 前后端分别维护网格规则、BFS 和途经点路线拼接，布局预览又有一份拼接循环。现在统一到 `grid.ts`，`pathfinding.ts` 只适配 Yjs 地图。保留原来的邻居访问顺序，避免等长路线选择改变怪物移动和攻击结果。
3. 攻击强化、自身攻速、MVP 层数和多个光环常量在战斗与界面中重复。现在统一到轻量 `towerRules.ts`，避免 UI 为读取规则引入整套战斗运行时。其他战斗纯计算归入 `combat/rules.ts`，内部状态类型归入 `combat/types.ts`。
4. `TowerGame.vue` 同时承载四个工具面板的完整模板及测试怪物表单。现在拆成组件，页面保留功能编排；组件始终挂载、内部控制可见性，保持关闭再打开时的表单状态。关闭信息面板的分支改为统一遍历。
5. 存档和布局存储重复维护打开数据库、请求、事务与连接释放。现在复用 `indexedDb.ts`，两个仓储保留各自的索引和裁剪规则。事务监听在执行请求前安装，请求与事务的失败均被观察，连接在 `finally` 中关闭。
6. 场景混有大量共享材质、几何体初始化和手写释放列表。现在由 `createSceneResources()` 创建并统一释放共享资源；动态对象、动画和场景生命周期继续由场景模块处理。
7. 包名、七个直接依赖及生成脚本属于旧编辑器或已不存在的脚本。已移除无引用依赖声明和失效命令，保留现有依赖版本并同步锁文件。README 更新为实际应用，Docker 运行镜像包含共享战斗代码。

页面从 1062 行缩至约 900 行；服务端战斗入口从 2137 行缩至 12 行，其战斗实现迁入共享核心，并非删除玩法。两个 IndexedDB 仓储合计从 188 行缩至 70 行，公共事务实现集中维护。整体以明确职责和减少重复为目的，不用总行数掩盖新增的回归测试和模块接口。

## 兼容性约束

- 保留 URL 参数、WebSocket 路径、消息类型和字段、Tick/快照频率、波次结算顺序及随机数调用顺序。
- 保留 Yjs 的 `square-towers-v1`、`player-build-states-v1`、`game-metadata-v1` 名称与数据格式。
- 保留 IndexedDB 名称 `gemtd-saves` / `gemtd-layouts`、版本 1、对象仓储和索引；不要求迁移已有存档。存档每房间最多 40 条，自定义布局最多 40 条。
- 保留现有样式、几何体/材质参数、候选与合成行为、测试怪物参数和面板关闭行为。
- 保留原工作区的单机模式变更；没有恢复到 Git HEAD 的旧实现。

## 保留的边界与后续维护

`useGameScene.ts` 仍然较大，场景事件、对象映射与插值共享很多可变状态；本次只抽出明确独立的共享资源。继续拆分应先覆盖指针拖动、多指手势、光环高亮和视觉效果的图像回归，以免把隐含顺序依赖变成跨模块问题。

服务端房间和 Yjs 文档仍保存在内存中，且未增加鉴权、持久化或空房间回收策略。房间客户端提交布局、合成、重置和测试请求的信任边界沿用原实现；这些属于服务产品策略，不在保持现有玩法的架构重构中更改。

单机/联机连接在挂载时创建，房间变化推荐通过导航重新加载；没有增加同一挂载实例内无缝切换传输方式。存档恢复仍涉及本地 Yjs 写入和战斗引擎恢复两个步骤，未引入分布式事务。

Three.js 仍使主 JS 包超过 Vite 默认 500kB 提示阈值；本次没有通过改变加载时机消除提示。未进行实际手机 GPU/触摸设备测试、生产环境长时间联机压测、容器镜像构建或全像素视觉对比。现有检查为兼容性提供可复现证据，不代表对未覆盖场景的绝对保证。
